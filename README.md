# 以 Meep 模擬矽光子微環調變器（2D FDTD）

本專案用開源 FDTD 軟體 [Meep](https://meep.readthedocs.io/) 模擬矽光子**微環調變器**（micro-ring modulator），輸出結構平面圖、穿透率對波長的光譜，並自動計算共振波長、Q 值、消光比等指標。程式已包成可重複呼叫的函式，目標是之後接上**逆向設計**（機器學習或最佳化演算法）。

> **狀態：** 流程已在真實 Meep 資料上跑通，並完成「解析度」與「gap」兩組掃描（見第 10 節）。目前採用 2D 等效折射率近似，結果用來驗證流程與看趨勢，**不代表真實元件的絕對數值**。主要發現：電壓造成的共振位移很穩定，但目前這組設計（R=3 µm）調變 ER 最高只有約 0.5 dB，瓶頸是環自身的損耗，而不是 gap。

## 1. 背景原理

**研究目標。** 以模擬為主，結合機器學習，對微環調變器做逆向設計：給定想要的光學表現（例如亮暗差大、損耗小），由演算法反推環半徑、間隙等結構參數，並比較不同機器學習演算法在準確度與運算時間上的差異。Meep 在這裡扮演「前向模擬器」：給一組結構參數，算出光譜與指標，作為訓練資料與驗證依據。

**Meep 的角色與限制。** Meep 只求解光（麥克斯威方程），不處理電學。因此本專案把「電壓」簡化成「折射率變化 Δn 與吸收變化 Δα」兩個輸入參數，分別跑「電壓 OFF」與「電壓 ON」兩次模擬後比較光譜。Δn、Δα 與載子濃度的關係可由 Soref 公式換算（目前程式以示意值輸入，尚未內建換算）。

微環調變器的運作原理（含共振為何會讓直波導出口出現凹谷）請見下一節 2.1。

## 2. 模擬架構

### 2.1 微環調變器怎麼運作

**元件組成。** 一條直波導（bus waveguide）、一個環形波導（ring），兩者之間隔著一條很窄的縫（gap，約 0.1 到 0.2 µm）。光從直波導左端進入、右端（through port）離開，我們量的就是右端剩下多少光。

```
            ┌──────────────┐
         ┌──┘   環 (ring)  └──┐
         │                    │
         └──┐              ┌──┘
            └──────┬───────┘
                   │ gap（耦合區）
 輸入 ═════════════╧═══════════════► 輸出（through port）
              直波導 (bus)
```

**光怎麼進到環裡（耦合）。** 光在波導內傳播時，有一小部分電場會滲到波導外面，稱為倏逝波（evanescent field）。gap 夠窄時，這部分電場會碰到環，把一部分光傳進去。用兩個係數描述：自耦合係數 `t`（直接通過的振幅比例）與交叉耦合係數 `κ`（進入環的振幅比例）。無損耦合器滿足 `t² + κ² = 1`。gap 越小，`κ` 越大，而且 `κ` 隨 gap 近似指數式變化，所以 gap 對耦合強度非常敏感。

**共振條件。** 光在環內繞一圈會累積相位：

```
φ = 2π · n_eff · L / λ        （L = 2πR 為環的周長，n_eff 為等效折射率）
```

繞一圈回來時，若相位剛好是 2π 的整數倍（`φ = 2πm`），這一圈的光與新進來的光同相，一圈一圈疊加，這就是共振：

```
λ_m = n_eff · L / m           相鄰兩個共振的間距（FSR） ≈ λ² / (n_g · L)
```

本專案 R=3 µm 時，較粗的掃描量到 FSR 約 41 到 44 nm，對應群折射率 n_g 約 3。

**為什麼共振時，直波導出口會出現凹谷（核心）。** 出口的光是兩條路徑的疊加，也就是干涉：

- **路徑 A**：光直接沿直波導通過，不進環。振幅是 `t · E_in`。
- **路徑 B**：光先耦合進環，在環裡繞了一圈（或很多圈），再耦合回直波導。耦合進去與耦合出來各帶一次 90° 的相位，合計 180°，所以路徑 B 相對路徑 A 是反相（符號相反）。

兩條路徑如何疊加，取決於繞圈相位 `φ`：

- **共振時（`φ = 2πm`）**：環內的光每一圈都同相累積，路徑 B 的強度很大，而且與路徑 A 反相，產生**相消干涉**，出口的光變少，穿透率 T 出現凹谷。
- **離開共振時**：每一圈的相位不同，不同圈的光互相抵消，路徑 B 很弱，幾乎沒有干涉，T 約等於 1。

換成能量的說法：共振時大量的光被「存」進環裡，環有損耗（材料吸收、彎曲輻射、側壁散射），這些光在環裡被消耗掉，沒有回到直波導，所以出口變暗。

> **重要：** 如果環完全沒有損耗，進環的光最後會全部回到直波導，只有相位被改變，T 永遠等於 1，不會有凹谷。凹谷是「耦合」與「損耗」的平衡所產生的。

令 `a` 為環繞一圈後振幅剩下的比例（`a = 1` 代表無損），標準的全通（all-pass）環形共振器穿透率為：

```
T(φ) = (a² − 2·a·t·cos φ + t²) / (1 − 2·a·t·cos φ + (a·t)²)

共振時（cos φ = 1）：  T_min = ( (a − t) / (1 − a·t) )²
```

**三種耦合狀態。** 凹谷多深，取決於「光進環的速度」與「光在環裡損失的速度」是否相當：

| 狀態 | 條件 | 共振時 T_min | 對應的 gap |
|---|---|---|---|
| 欠耦合（under-coupled） | 進環速度 < 損耗速度（`t > a`） | 凹谷淺 | gap 偏大 |
| 臨界耦合（critical） | 兩者相等（`t = a`） | 理論上降到 0（完全消光） | 剛好 |
| 過耦合（over-coupled） | 進環速度 > 損耗速度（`t < a`） | 凹谷又變淺 | gap 偏小 |

用 Q 值表示更直觀：令 `Q_c` 對應「光耦合進出環」的速率、`Q_i` 對應「環自身損耗」的速率（Q 越大代表速率越慢），則

```
1/Q_L = 1/Q_i + 1/Q_c                  （Q_L 是實際量到的 Q，FWHM = λ₀ / Q_L）
T_min = ( (1/Q_i − 1/Q_c) / (1/Q_i + 1/Q_c) )²
```

當 `Q_c ≫ Q_i`（進環很慢）就是欠耦合，凹谷很淺；`Q_c = Q_i` 是臨界耦合。

**怎麼拿來做調變器。** 對矽施加電壓，改變載子濃度，透過電漿色散效應（Soref 效應）改變折射率 `Δn`（以及吸收 `Δα`），等效折射率 `n_eff` 改變，繞圈相位 `φ` 隨之改變，共振波長位移：

```
Δλ ≈ λ · Δn_eff / n_g
```

雷射波長固定，放在凹谷的斜坡附近。電壓 ON/OFF 時凹谷左右移動，雷射波長處的穿透率隨之改變，亮暗即對應 1 與 0。亮暗差（OMA）取決於兩件事：位移相對於凹谷寬度（`Δλ / FWHM`），以及凹谷夠不夠深（ER）。吸收的改變 `Δα` 則會改變 `a`，進而改變凹谷的深度與寬度。

**Meep 在這裡做什麼。** Meep 不使用上面的公式，而是直接在空間與時間的格點上推進麥克斯威方程：從直波導左端送入一個寬頻脈衝，等光通過、環內的光漏完之後，對出口記錄到的場做傅立葉轉換，得到各波長的穿透率。上面的公式只用來「解讀」模擬結果、判斷設計落在哪個耦合狀態。

### 2.2 模擬流程

```
              y
              ^        ┌──────────┐
              |      ┌─┘   環     └─┐        環：圓心在 (0,0)，中心線半徑 R
              |      │    (矽)      │        直波導：位於環下方，gap 為間隙
              |      └─┐          ┌─┘
              |        └──────────┘
   光源 ─►  ═════════════════════════════►  through 監測器
              └──────────── 直波導 ───────────> x
```

1. **幾何**：矽（等效折射率 2.8）的直波導與環，背景為 SiO₂（折射率 1.44），四周為 PML 吸收邊界。
2. **光源**：直波導左端放寬頻高斯脈衝（Ez 極化）。
3. **監測**：直波導右端（環的耦合區之外）放 flux 監測器，記錄各頻率的穿透功率。
4. **三次模擬**：
   - 參考：只有直波導，用來扣掉光源頻譜與波導本身的影響。
   - 電壓 OFF：環為原本的矽。
   - 電壓 ON：環的折射率加上 `DN_ON`，並加入吸收 `DALPHA_ON`。
5. **歸一化**：穿透率 `T(λ) = 有環的功率 / 參考功率`。
6. **指標萃取**：從 `T(λ)` 抓出凹谷位置、半高寬、Q、消光比，並比較 OFF/ON 得到調變指標。
7. **有效性檢查**：檢查凹谷是否可信（見第 8 節），不合格則標記無效或自動重試。
8. **停止條件**：等環內場衰減到 `DECAY` 以下才停止（Q 越高跑越久）。

## 4. 使用方式

保留micro_ring_modulator_meep.py, mrm_sweep_analysis.xlsx, sweep_resolution.py, README.md其餘可刪除

```bash
# 單核執行
python micro_ring_modulator_meep.py

# 平行執行（需安裝 MPI 版 Meep）
mpirun -np 4 python micro_ring_modulator_meep.py
```

執行結束後，終端機會印出各項指標，並在目前資料夾產生圖檔與光譜資料。

放大圖的範圍由程式開頭的 `PLOT_ZOOM` 控制（兩個凹谷外側各多留幾倍 FWHM，預設 1.5，數字越小畫面越放大）。長時間模擬跑完後，想調整圖的範圍，不必重跑 Meep：

```bash
python replot_from_npz.py --zoom 1.0            # 更放大
python replot_from_npz.py --xlim 1537 1542      # 手動指定 x 軸範圍 (nm)
```

**第一次使用建議先用低成本設定確認流程**：在 `PARAMS` 中把 `RESOLUTION` 設為 20 到 25、`NFREQ` 設為 200 到 600，確認結果合理後再提高解析度與降低 `DECAY`。

## 5. 參數說明

所有參數集中在程式開頭的 `PARAMS`（長度單位 µm）。參數分兩類：**設計參數**是真實元件的結構或物理量，是逆向設計要調整的旋鈕；**數值參數**只影響模擬算得準不準、跑多久，不是設計的一部分。

| 參數 | 預設值 | 類型 | 說明 |
|---|---|---|---|
| `R` | 3.0 | 設計 | 環中心線半徑 |
| `W` | 0.5 | 設計 | 波導寬度（環與直波導相同） |
| `GAP` | 0.20 | 設計 | 直波導邊緣與環邊緣的間隙，決定耦合強度 |
| `DN_ON` | −0.004 | 設計 | 電壓 ON 的折射率變化（示意值） |
| `DALPHA_ON` | 0.0 | 設計 | 電壓 ON 的額外吸收，單位 cm⁻¹（先設 0，只看折射率造成的位移） |
| `N_SI` | 2.8 | 材料 | 矽的等效折射率（2D 近似） |
| `N_CLAD` | 1.44 | 材料 | 包覆層 SiO₂ 的折射率 |
| `RESOLUTION` | 40 | 數值 | 每 µm 的像素數 |
| `NFREQ` | 1200 | 數值 | 頻率取樣點數，決定光譜的細緻度 |
| `DECAY` | 1e-6 | 數值 | 場衰減到多小才停止，越小越準但越慢 |
| `DPML` | 1.0 | 數值 | PML 厚度 |
| `WVL_MIN`, `WVL_MAX` | 1.535, 1.555 | 數值 | 掃描波長範圍（要小於 FSR，且涵蓋 OFF 與 ON 的凹谷） |

主要函式：

| 函式 | 用途 |
|---|---|
| `run_spectrum` | 跑一次模擬，回傳各頻率的穿透功率 |
| `analyze_dip` | 從光譜找凹谷，回傳 λ₀、FWHM、Q、ER |
| `modulator_metrics` | 比較 OFF/ON，回傳 OMA、調變 ER、IL |
| `check_dip` | 檢查一條光譜的凹谷是否可信（見第 8 節） |
| `adjust_for_retry` | 檢查不合格時，嘗試自動修正（平移窗口、加嚴 DECAY） |
| `predict_center` | 由已知結果預測新 R 的共振位置，用來放置掃描窗口 |
| `evaluate` | 從參數到指標的完整流程，含檢查與自動重試（逆向設計用） |
| `figure_of_merit` | 把指標變成單一分數，無效設計給固定懲罰分數 |

## 7. 指標定義

| 指標 | 定義 |
|---|---|
| `λ₀` | 凹谷最低點對應的共振波長 |
| `FWHM` | 在最亮與最暗的正中間高度所量得的凹谷寬度 |
| `Q` | `λ₀ / FWHM`，越高共振越尖銳（這裡的 Q 是實際量到的 Q_L） |
| `ER` | `10·log10(T_max / T_min)`，單一凹谷的深度（dB） |
| 共振位移 | OFF 與 ON 的 `λ₀` 差 |
| `OMA` | 在雷射波長 `λ_L` 的 `\|T_on − T_off\|`，調變振幅 |
| 調變 `ER` | `10·log10(亮 / 暗)`，在 `λ_L` 處比較兩狀態 |
| `IL` | `−10·log10(亮狀態的 T)`，插入損耗 |

目前程式把 `λ_L` 取在「OFF 與 ON 差最大」的波長。

## 8. 資料有效性檢查

逆向設計會用大量不同參數呼叫 `evaluate`。參數一改，共振位置就會移動（例如 `R` 變 1.7%，共振約移 26 nm），可能跑出掃描窗口、窗口內出現兩個共振，或模擬沒跑到收斂。這些情況下 `analyze_dip` 仍會算出數字，但數字是錯的。因此 `evaluate` 會對 OFF 與 ON 兩條光譜做檢查，並在回傳的字典中帶有 `valid` 與 `reason`：

| 錯誤代碼 | 意義 | 自動處理 |
|---|---|---|
| `not_converged` | T 明顯大於 1，環內的光還沒漏完就停了 | 把 `DECAY` 縮小 100 倍後重跑 |
| `no_dip` | 凹谷深度低於 0.1 dB（共振可能完全在窗口外，或耦合太弱而太淺） | 無法自動修正 |
| `edge_low` / `edge_high` | 凹谷在窗口邊緣，可能被切掉 | 朝凹谷那一側平移窗口後重跑 |
| `incomplete` | 凹谷量不到半高寬 | 同上，平移窗口 |
| `multi` | 窗口內有多個共振 | 無法自動修正，請縮小 `WVL_MIN`、`WVL_MAX` 或改 `R` |

模擬本身失敗（當機、記憶體不足）也會被攔下，回傳 `valid=False`，不會讓批次中斷。

**限制：** 窗口追蹤只在共振「剛好跑出邊緣、仍看得到凹谷的一側」時有效（以預設參數約為 `R` 變動 1% 內）。若共振完全離開窗口，光譜是平的，程式無法知道該往哪個方向移，會回報 `no_dip`。此時請用 `predict_center` 預測共振位置，並透過 `center_um` 引數放置窗口。這套檢查邏輯先用合成光譜測試，再由第 10 節的真實掃描實際使用（沒有觸發重試）。

**門檻的現況：** `no_dip` 的門檻 0.1 dB 是經驗值。第 10 節的掃描中，解析度 40 與 50 兩組的凹谷 ER（0.092、0.079 dB）略低於門檻而被標為 `valid=False`，但它們的位移與 Q 都與其他組一致，是真實但很淺的凹谷，不是模擬失敗。建議之後把門檻降到約 0.05 dB（約為雜訊的 4 倍）。

**`valid=False` 時，其餘數值僅供除錯，不要拿去訓練。**

## 9. 解析度與 gap 掃描

`sweep_resolution_gap.py` 批次掃描「解析度 × gap」，每組結果寫入 CSV；`mrm_sweep_analysis.xlsx` 讀取這份 CSV，自動算出收斂判定與衍生數值。為什麼要掃這兩個參數、它們的定義與對設計的影響，見第 10 節。

```bash
# 解析度收斂測試（gap 固定）
python sweep_resolution_gap.py --resolutions 25 40 50 --gaps 0.20

# gap 掃描（解析度固定）
python sweep_resolution_gap.py --resolutions 40 --gaps 0.10 0.12 0.15 0.20
```

- 每跑完一組就寫入 CSV；中斷後重新執行同一個指令，已有結果的組合會自動跳過。
- 每組的掃描窗口以上一組有效結果的共振波長為中心（`--center-nm` 指定第一組的位置）。
- 無效結果也會寫入並附原因。
- 目前 CSV **沒有記錄** `DECAY` 與 `NFREQ`（沿用 `PARAMS` 的值），之後建議加入，才能完整重現。
- 試算表的「掃描資料」分頁從 A5 貼上 CSV 資料列（不含標題列）；「時間估算」分頁可由一次實測推算其他解析度的耗時。

### 10.2 解析度（RESOLUTION）：為什麼要掃、它是什麼、對設計有什麼影響

**定義。** `RESOLUTION` 是每 µm 長度切成幾個格點。Meep 把空間切成方格，格點邊長是 `1 / RESOLUTION` µm，並用階梯狀的方格去近似圓形的環與很窄的 gap：

| RESOLUTION | 格點邊長 | gap = 0.20 µm 約幾格 | 環寬 0.5 µm 約幾格 |
|---|---|---|---|
| 25 | 40 nm | 5 | 12.5 |
| 40 | 25 nm | 8 | 20 |
| 50 | 20 nm | 10 | 25 |

**為什麼要取樣這個參數。** 它**不是設計參數**（真實元件沒有「格點」），而是決定「算得準不準」的數值參數。如果模擬結果會隨著解析度改變，代表我們量到的是格點造成的假象，而不是元件的物理。因此用同一個設計，換不同解析度各跑一次，看結果有沒有趨於穩定，這就是**收斂測試**。它同時決定成本：耗時大約隨解析度的 2.8 次方增加，所以要在準確度與運算時間之間取捨。

**對設計與研究的影響。** 解析度會改變「環的有效光程」和「gap 的耦合強度」，所以共振波長與凹谷深度的絕對值會跟著改變；但位移、gap 越小凹谷越深這類**相對趨勢**不受影響。對逆向設計而言，同一批資料必須使用同一個解析度，否則共振位置的系統差（1 到 5 nm）會被演算法誤當成設計的效果。

**結果（gap = 0.20 µm）：**

| 解析度 | 共振 λ₀ (nm) | 位移 (nm) | FWHM (nm) | Q | ER (dB) | 耗時 (分) |
|---|---|---|---|---|---|---|
| 25 | 1540.360 | −2.149 | 0.383 | 4027 | 0.121 | 6.2 |
| 40 | 1535.034 | −2.151 | 0.373 | 4118 | 0.092 | 21.6 |
| 50 | 1533.826 | −2.147 | 0.386 | 3977 | 0.079 | 43.3 |

**判讀：**

- **位移已收斂。** 三個解析度都是 −2.15 nm。由 `Δλ ≈ λ·Δn/n_g` 反推（假設 Δn_eff ≈ Δn），n_g 約 2.86，與 FSR 估出的約 2.96 同量級。「折射率變化 → 共振位移」這條鏈很穩，`DN_ON` 可當成可靠的設計旋鈕。
- **共振波長沒有收斂。** 隨解析度提高往短波長漂移了 5.3 nm，再漂 1.2 nm，漂移量在縮小，但到 50 仍未停止（相鄰差遠大於試算表預設的 0.2 nm 門檻）。絕對波長不能當真，只能比較同一解析度下的相對結果。
- **Q 與 ER 的判斷要保守。** Q 在三個解析度之間只差約 3%，看似穩定；但第一次試跑（推測同為解析度 25）的 Q 是 6104，與這次的 4027 差了 34%（FWHM 為 0.252 與 0.383 nm，ER 為 0.133 與 0.121 dB，共振位置則幾乎相同）。兩次的 `DECAY`、`NFREQ`、掃描窗口可能不同，原因未確認。這說明凹谷只有 2 到 3% 深時，用半高寬量出的 Q 誤差可能達三成，所以「Q 沒有隨解析度改變」只能說沒有看到明顯趨勢，不能說已經證明收斂。ER 則隨解析度單調下降（0.121 → 0.092 → 0.079 dB），幅度大於上面的重複量測差異（約 10%），可能是真實趨勢：格點變細，gap 畫得更準，耦合變得更弱。
- **耗時。** 6.2、21.6、43.3 分鐘，對應的耗時隨解析度的指數約 2.8，略低於理論推估的 3 次方。

**結論：** 大批資料建議用 `RESOLUTION = 40`（約 7 到 22 分鐘一組），最後挑出的好設計再用 50 以上驗證；40 與 50 之間共振位置仍差 1.2 nm，相對於 gap=0.20 時 0.37 nm 的 FWHM 並不小，因此只做資料集內的相對比較，不要與其他解析度的資料混用。

### 10.3 間隙（GAP）：為什麼要掃、它是什麼、對設計有什麼影響

**定義。** `GAP` 是直波導邊緣到環外緣的最短距離（µm），不是中心距。直波導中心到環中心的距離為 `R + W + GAP`。

**為什麼要取樣這個參數。** gap 是調整耦合強度（`κ`）的主要旋鈕，決定設計落在「欠耦合、臨界耦合、過耦合」哪一種（見 2.1）。只改 gap、其他全固定，觀察凹谷深度、寬度、Q 怎麼變，就能判斷目前設計在哪一側、應往哪個方向調。gap 也受製程限制（太窄做不出來），所以先看它有多大效果很有價值。

**對設計的影響（一般原理）。** gap 變小：`κ` 近似指數式變大，光更容易進環。欠耦合時，這使凹谷變深（ER 與 OMA 變大），同時實際量到的 Q 變低、凹谷變寬。凹谷變寬代表光在環內停留時間短，光學頻寬較大，一般有利於更快的調變，但也需要更大的位移才能分開亮暗。gap 小過頭則會進入過耦合，凹谷反而變淺。

**結果（`RESOLUTION` = 40）：**

| gap (µm) | 共振 λ₀ (nm) | FWHM (nm) | Q | OFF 凹谷 ER (dB) | OMA | 調變 ER (dB) | 位移/FWHM | 耗時 (分) |
|---|---|---|---|---|---|---|---|---|
| 0.10 | 1535.52 | 1.385 | 1109 | 0.607 | 0.114 | 0.53 | 1.55 | 6.8 |
| 0.12 | 1535.33 | 1.099 | 1397 | 0.336 | 0.068 | 0.31 | 1.96 | 8.2 |
| 0.15 | 1535.17 | 0.741 | 2073 | 0.179 | 0.039 | 0.17 | 2.90 | 11.8 |
| 0.20 | 1535.03 | 0.373 | 4118 | 0.092 | 0.021 | 0.09 | 5.77 | 21.6 |

（位移在四組都約為 −2.15 nm。「位移/FWHM」取位移的絕對值。）

**判讀：**

- **趨勢乾淨且符合物理。** gap 越小，凹谷越深、越寬、Q 越低；Q 的變化達 3.7 倍，遠大於量測誤差，所以趨勢是真的。耗時也隨 Q 增加（6.8 分到 21.6 分），因為 Q 越高，環內的光漏得越慢。
- **目前的設計落在欠耦合。** 判斷依據是「gap 變小，凹谷反而變深」：在欠耦合時增加耦合會使凹谷變深，過耦合則相反。
- **用簡單環模型粗估耦合與損耗**（由 Q 與 ER 反推，假設 `T_max = 1`，只是量級參考）：

| gap (µm) | Q（實測） | `Q_c`（光進環，粗估） | `Q_i`（環自身損耗，粗估） |
|---|---|---|---|
| 0.10 | 1109 | 約 3.3×10⁴ | 約 1.1×10³ |
| 0.12 | 1397 | 約 7.4×10⁴ | 約 1.4×10³ |
| 0.15 | 2073 | 約 2.0×10⁵ | 約 2.1×10³ |
| 0.20 | 4118 | 約 7.8×10⁵ | 約 4.1×10³ |

  即使 gap 縮到 0.10 µm，`Q_c` 仍比 `Q_i` 大約 30 倍，也就是光進環的速度遠慢於環裡損失的速度，所以凹谷很淺。另外，粗估出的 `Q_i`（環自身損耗）會隨 gap 變小而下降，理論上環自身的損耗不該與 gap 有關，這表示耦合區可能額外漏光，或這個簡單模型不完全適用，需要更多資料確認。
- **沒有任何一組達到調變 ER 3 dB 的目標**（最高 0.53 dB，OMA 最高 0.114）。

### 10.4 綜合結論與對設計的意義

1. **逆向設計的搜尋範圍必須包含 R。** 只調 gap，從這批資料看達不到目標：gap 已縮到 0.10 µm，Q 只剩約 1100，凹谷變寬（位移/FWHM 只剩 1.55），OMA 仍只有 0.11。更有力的槓桿應是降低環自身損耗，也就是加大環半徑 R（彎曲損耗隨半徑變小）。這是推測，需要用掃描驗證。
2. **`DN_ON` 是可靠的設計旋鈕。** 位移對解析度與 gap 都很穩定，約 −2.15 nm。
3. **解析度要固定。** 同一批資料用同一個解析度，並在紀錄中保存 `RESOLUTION`、`DECAY`、`NFREQ`。
4. **gap 掃描等於一張迷你的設計空間地圖。** 之後機器學習找出的最佳 gap，可以與這張地圖互相對照，檢查演算法有沒有找對。

### 10.5 量測的可信度與限制

- 淺凹谷的 Q 與 ER 量測誤差大（Q 可能達三成），以半高寬量 Q 在這種條件下不夠穩，建議改用洛倫茲曲線擬合，或用 Meep 的 Harminv 直接由時域訊號求 Q。
- 共振波長的絕對值隨解析度漂移，尚未收斂。
- 早期一次試跑（`GAP`=0.15、`DALPHA_ON`=15，設定記錄不完整）曾看到電壓 ON 的凹谷比 OFF 更深，但在欠耦合下，加入損耗理論上應使凹谷變淺，兩者不一致。可能原因是當時 `DECAY` 較鬆，高 Q 的 OFF 凹谷被截斷而偏淺，但這只是假設，未驗證，建議在固定設定下重做 `DALPHA_ON` 測試。
- 上述所有結果都是 2D 等效折射率近似，尚未與 3D 或實驗比對。

### 10.6 下一步

1. **掃 R**：例如 R = 4、5、6（gap 約 0.12，解析度 25 到 30 即可看趨勢），看 Q 與 ER 是否明顯上升。R 改變時共振位置會大幅移動，需配合 `predict_center`（目前 `sweep_resolution_gap.py` 尚未支援掃 R，需新增）。
2. **改善凹谷量測**：洛倫茲擬合或 Harminv。
3. **完整記錄設定**：CSV 加入 `DECAY`、`NFREQ`。
4. **調整門檻與收斂判定**：`no_dip` 門檻降到約 0.05 dB；試算表的收斂判定改看位移、Q、ER 的變化，不要用絕對共振波長。
5. **重做 `DALPHA_ON` 測試**，確認吸收對凹谷深度的影響。

## 11. 限制與注意事項

- **2D 等效折射率近似**：以固定的 `N_SI` 取代真實矽波導的三維模態，絕對的共振波長、FSR、Q 都與真實元件不同。需要定量時請改用 3D 或以 MPB 求 n_eff。
- **波導可能不是單模**：以對稱平板波導粗估，`W`=0.5 µm、折射率 2.8 與 1.44 時 V 約 2.4，大於單模截止值（約 π/2），可能存在第二個導波模態。光源主要激發基模，但仍可能有少量能量耦合到高階模。這是粗估，尚未用 MPB 驗證。
- **Δn、Δα 為示意值**：尚未接上電壓、PN 接面與 Soref 公式的換算，且整個環都套用同樣的 Δn（真實元件只有部分區域摻雜），位移量會被高估。
- **光源為簡化設定**：使用 Ez 點源沿波導截面鋪開，主要激發基模；若要更乾淨的基模激發，可改用 `mp.EigenModeSource`。
- **解析度**：`RESOLUTION=20` 時像素為 50 nm，`GAP` 只有 4 個像素（gap=0.2 µm），共振位置與深度會有誤差。最終結果請用較高解析度重跑並確認收斂。
- **取樣與停止條件**：`DECAY` 太鬆會在環內場尚未衰減完時就停止，頻譜出現假的起伏甚至 T>1；`NFREQ` 太少會漏掉窄的凹谷。
- 程式尚未與實驗數據或其他模擬軟體比對。

## 12. 接上逆向設計

`evaluate(p)` 接受一組參數字典，回傳指標字典，可直接當作最佳化或機器學習的**前向模擬器**：

```python
from micro_ring_modulator_meep import (PARAMS, evaluate, figure_of_merit,
                                       predict_center)

cache = {}                                  # 參考光譜快取，多次呼叫共用，省掉重複的參考模擬
p = dict(PARAMS, GAP=0.12)                  # 修改要探索的參數
m = evaluate(p, ref_cache=cache)            # 回傳 Q、ER_dB、OMA、IL_dB、shift_nm、valid、reason ...

if m["valid"]:                              # 只有可信的結果才拿來訓練
    score = figure_of_merit(m)              # 單一分數，越大越好

# 改了 R 之後，先預測共振位置再放窗口（lam_ref 是已知結果的 OFF 共振波長，單位 µm）
center = predict_center(R_new=5.0, R_ref=3.0, lam_ref_um=1.5350)
m2 = evaluate(dict(PARAMS, R=5.0), ref_cache=cache, center_um=center)
```

`figure_of_merit` 對無效設計回傳固定的懲罰分數，而不是 nan，讓最佳化器避開那一區；原因仍保留在 `reason`。其中的加權只是示範，請依實際目標修改。`example_scan_R` 是一個掃描 `R` 並自動追蹤共振的完整範例。

依第 10 節的結果，建議的設計變數是 `R`、`GAP`、`W`、`DN_ON`（其中 `R` 與 `GAP` 最重要）。典型做法有兩種：

- **資料集加代理模型**：批次掃描參數，建立「參數 → 光譜或指標」資料集（只收 `valid=True` 且解析度一致的資料），訓練神經網路當代理模型，再用最佳化演算法反推設計。
- **梯度法**：Meep 內建 adjoint solver，可對像素化的形狀求梯度（需另外把結構改寫成可微分的設計區域）。

Meep 每次模擬耗時是主要瓶頸，建議先用低解析度的 2D 版本做大量掃描，最後再用高解析度驗證最佳解。

## 13. 執行時間

下表是第 10 節掃描的實測耗時（單次 `evaluate`，含參考、OFF、ON 三次模擬；使用的電腦與核心數未記錄，只能當相對比較）：

| 設定 | 耗時（分鐘） |
|---|---|
| `RESOLUTION`=25，gap=0.20 | 6.2 |
| `RESOLUTION`=40，gap=0.20 | 21.6 |
| `RESOLUTION`=50，gap=0.20 | 43.3 |
| `RESOLUTION`=40，gap=0.10 | 6.8 |
| `RESOLUTION`=40，gap=0.12 | 8.2 |
| `RESOLUTION`=40，gap=0.15 | 11.8 |

- 耗時大約隨解析度的 2.8 次方增加。
- 耗時大致與 Q 成正比（gap=0.10 與 0.20 的 Q 差 3.7 倍，耗時差 3.2 倍），因為要等環內的光漏完。
- 可用 `mpirun -np 4` 平行加速；實際加速倍數視機器而定，尚未量測。
- `mrm_sweep_analysis.xlsx` 的「時間估算」分頁可依自己的實測推算其他解析度。
